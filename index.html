How to use this roadmap

The plan assumes you already know programming fundamentals from C++/JavaScript. It does not assume you know Python's scientific ecosystem or ML.

Guiding rule: Do not rush to LLM frameworks. First learn how data is represented, how a model learns, how to evaluate it, and how to deploy it. Modern AI engineering still depends on these foundations.

Completion standard

Mark a week complete only when you have (1) studied the topic, (2) coded or solved the practice, and (3) prepared a student-facing explanation. Watching a lecture alone does not count as completion.

48-week syllabus, deadlines and practice

Open each week for lecture targets, study tasks, practice, teaching preparation and a concrete submission. Use the Sunday deadline as a checkpoint, not as a reason to rush.

Student teaching workflow

For every topic you learn, produce a small, consistent teaching pack. This makes the roadmap useful for students who are less comfortable with English lectures.

Before teaching

Watch/read the source. Verify definitions, APIs and examples. Write a one-sentence learning objective. List prerequisites.

During the lesson

Explain in conversational Hindi. Keep standard technical vocabulary in English. Start with intuition, then code, then edge cases.

After the lesson

Publish notes, 3–5 practice questions, one worked solution and a short recap. Link the original university material.

Quality check

Run every code block. Check outputs. Label optional/advanced content. Avoid teaching a library API from memory when docs may have changed.

Phase exit gates

  • After Python: Can write, test and debug small Python programs without translating every line from JavaScript/C++.
  • After math/data: Can explain vectors, distributions, train/test split and basic data visualization.
  • After classical ML: Can build a baseline, choose metrics, diagnose overfitting and explain model limitations.
  • After deep learning: Can write a PyTorch training loop and interpret loss/validation curves.
  • After engineering: Can package, test, serve and monitor a model as a software service.
  • After LLM phase: Can explain retrieval, generation, evaluation and when a simpler non-LLM solution is better.

Keep the curriculum current

AI moves quickly. The fundamentals do not need to be rewritten every month, but libraries, recommended workflows and model capabilities do change.

What to verify before publishing a lesson

  • Python: Check the supported Python version and package installation instructions on the official project site. Avoid hardcoding old version numbers in teaching notes unless the lesson requires them.
  • Libraries: Verify current stable docs for NumPy, Pandas, Scikit-learn and PyTorch. Record the version used to run examples.
  • ML practice: Teach leakage prevention, proper train/validation/test separation, baselines, cross-validation where appropriate, class imbalance and meaningful metrics.
  • Deep learning: Teach tensors, autograd, optimization, data loaders, validation, checkpointing and reproducibility before advanced architectures.
  • LLMs: Cover tokenization, embeddings, attention, context windows, retrieval, evaluation, tool use and limitations. Don't equate prompt engineering with all of AI engineering.
  • Deployment: Include input validation, latency/cost, logging, model/data versioning, privacy and monitoring. A notebook alone is not a production system.

Source-of-truth policy

Use university lecture notes for conceptual teaching. Use official project documentation for APIs and installation. Use papers or technical reports for claims about new methods. Date-stamp claims that may change. If two sources disagree, explain the difference rather than silently choosing one.
